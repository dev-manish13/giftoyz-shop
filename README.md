# GifToyz Shop

Full-stack e-commerce site for **GifToyz Nepal**, a gift shop selling tumblers, plush toys
and teddies with delivery across Nepal. Live at **[giftoyz.com](https://giftoyz.com)**.

Built and run on Cloudflare's free tier: one Worker serves the storefront, the admin
dashboard and the API, with D1 (SQLite) for data and R2 for product media.

## Features

**Storefront**
- Product catalog with categories, colours and occasions, search and a persistent cart
- English and Nepali (Devanagari) UI, light and dark themes
- Checkout with live delivery fees for 300+ places, weight-based pricing, home delivery or branch pickup
- Order tracking by order ID or courier number + phone, with the courier's live timeline
- Printable bills, verified-buyer reviews, SEO (per-page meta, Open Graph, JSON-LD, sitemap)

**Admin dashboard** (`/admin`)
- Orders: payment confirmation, status, one-click shipment creation with the NCM courier API
- Products: CRUD, image upload with in-browser resizing to AVIF/WebP/JPEG (HEIC supported)
- Catalog setup, banners with schedules, delivery-rate refresh from the courier, shop settings
- New-order alerts to Telegram

**Payments**: manual wallet/bank QR flow today; a Khalti ePayment v2 integration is built in
and switches on only when its key is configured (payment is marked paid only after a
server-side lookup matches the transaction and amount).

## Architecture

```
Browser ── HTML/JS/CSS (built by build/build.py)
   │
   ▼
Cloudflare Worker (TypeScript, Hono)          cloudflare/
   ├─ pages: injects meta, JSON-LD, CSP nonce, catalog/settings data
   ├─ /api/*: catalog, orders, tracking, reviews, admin
   ├─ D1 (SQLite)   orders, products, rates, settings
   ├─ R2            product photos, banners, QR codes
   └─ Cron triggers courier status poll (15 min), daily rate sync
          │
          ▼
   NCM courier API · Telegram Bot API · Khalti (dormant)
```

`server/` is the original **FastAPI** (Python) version of the same API, kept as a reference
implementation and fallback. The Worker keeps the same API paths and JSON shapes, so the
frontend works with either. The migration plan is in [`REBUILD.md`](REBUILD.md).

## Tech stack

| Layer | Tech |
|---|---|
| Frontend | Vanilla JS, HTML generated by a Python build step, CSS custom properties |
| Edge backend | Cloudflare Workers, Hono, Zod, D1, R2, Cron Triggers, Wrangler |
| Reference backend | Python, FastAPI, pydantic-settings, SQLite, httpx |
| Testing | Vitest in `workerd` (Cloudflare), pytest (FastAPI) |

## Security

- Server-side prices and stock checks; client totals are never trusted
- Timing-safe admin key comparison with failed-attempt limiting and rate limits
- Strict Content-Security-Policy with per-request nonces, security headers on every response
- Order tokens stored hashed; phone numbers stored as peppered digests
- Courier shipment creation is idempotent and only retried when the request never left
- All secrets live in Wrangler secrets / local `.env` files, never in the repo

## Run locally

```bash
# Worker (production stack)
cd cloudflare
npm install
cp .dev.vars.example .dev.vars   # test values only
npm run dev                       # local Worker with D1/R2 emulation
npm test                          # Vitest suite
npm run typecheck

# FastAPI reference server
cd server
cp .env.example .env
pip install -r requirements-dev.txt
pytest -q
PORT=8091 bash run.sh
```

Regenerate the HTML after editing `build/pages.py` or `build/pages2.py`:

```bash
python3 build/build.py --local
```
